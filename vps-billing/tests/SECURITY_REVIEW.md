# 安全审查摘要

本记录覆盖 API 权限、会话与 CSRF、资源所有权、金额与幂等、展示设置、数据库迁移、事务和备份边界。它是工程审查记录，不是渗透测试认证或生产安全保证。当前接口约定见 [CONTRACT](../docs/CONTRACT.md)，安全配置与响应要求见 [SECURITY](../docs/SECURITY.md)，实际执行证据及其范围见 [VALIDATION](../docs/VALIDATION.md)。

## 已修复的具体问题

| 范围 | 问题与处理 |
|---|---|
| 数据访问与汇总 | 账单详情曾依赖最近 1,000 条列表，导致旧账单不可访问；现直接按资源与所有者查询。金额和数量汇总改用完整 SQL 聚合及只读一致性快照，不受列表上限影响。管理员详情使用独立只读权限，并隔离迟到的界面请求结果。 |
| 来源与代理 | 增加规范化 Host/Origin 校验、可信代理 CIDR 与 `X-Real-IP` 校验；非可信来源的转发头不参与身份判断。IPv6 地址归一化防止同一地址用不同文本绕过限速；启动拒绝会使合法浏览器请求失败的非规范 `APP_ORIGIN`。 |
| 输入与连接 | JSON 请求按实际媒体类型检查，拒绝伪造后缀；MySQL TLS 配置拒绝意外明文回退。同机 Unix socket 的明确例外及权限要求见安全文档。 |
| 金额与币种 | JavaScript 浮点除法曾使最大安全整数金额少显示一分，现使用 BigInt 整数与余数格式化；后端金额及汇总限制精确整数范围。迁移 005 使用按字节匹配的 CNY/USD 约束，拒绝大小写和重音变体。各币种独立定价，不隐式换汇。 |
| 下单重试 | 超时后再收到 401、403 或限流，不能证明原订单未创建；现保留原幂等键与请求内容，重试前刷新会话并按账户隔离。确定的首次输入错误允许纠正。MySQL 死锁及锁等待超时最多尝试三次，每次回滚并遵守请求取消。 |
| 历史记录 | 订单与账单同时保存开具方快照，修正字段不一致及共享引用问题；更改设置或价格不会改写历史金额、币种和身份。缺少旧身份时不补用当前公司资料。 |
| 设置与插件 | 设置仅管理员可写，要求 CSRF、版本检查及事务审计；公开字段与管理字段分离，文本、链接和界面规则一致。主题与标志为固定选项，无任意 HTML/CSS/脚本或远程素材执行入口。支付与邮件注册表仅管理员可读，不返回配置秘密。 |
| 迁移与事务 | 历史验收的迁移 1–5 在锁内校验连续版本、checksum 和实际结构；中断恢复核对定义，仅移除已知原始约束并保留自定义约束。拒绝未知版本、缺口、checksum 变化及冲突或失效约束。订单 outbox 写入失败回滚订单、账单、审计与幂等预留；设置审计失败回滚内容及 revision。 |
| 备份 | 并发备份使用唯一临时文件、不可覆盖的最终文件及可移动校验清单；原生脚本检查输入路径、权限和目标边界。实际恢复结果与适用范围见验证记录。 |

## 保留的限制

- 支付、自动邮件通知、webhook 结算、退款、完整账本/对账及 VPS 开通尚未实现；官方 SMTP 默认关闭，仅支持管理员配置和测试，新增行为及验收以对应源码和 [插件说明](../docs/PLUGINS.md)为准；checkout 保持失败关闭。`order.created` 仅写入持久 outbox，没有消费租约、重试、死信或投递去重；待付款事件不是开通授权。插件边界是可信编译代码接口，不是恶意插件隔离机制。
- 尚无邮件所有权验证、密码恢复/修改、管理员 MFA、完整账户封禁及用户撤销全部会话流程。退出登录会撤销当前会话；每次请求从服务端会话加载用户并核对角色，密码在登录时验证。
- 审计覆盖订单和设置变更，不是完整认证/管理事件审计或不可篡改财务账本。会话、幂等、outbox 与审计数据仍需明确保留策略，不能仅为节省空间删除财务历史。
- 登录限速为进程内计数，重启会重置，多实例不共享；真实代理链、共享出口和边缘滥用控制仍需针对部署环境验证。列表最多返回 1,000 条，尚无分页与完整导出合同；正确汇总和直接账单查询不消除此限制。
- 浏览器刷新后，不确定下单请求的客户端状态不持久化。必须先核对历史订单，不能换新幂等键并假定前次未执行。
