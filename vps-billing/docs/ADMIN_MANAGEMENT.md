# 管理员管理边界

[使用入门](GETTING_STARTED.md) · [API 契约](CONTRACT.md) · [验证记录](VALIDATION.md)

管理员是全站业务管理身份，不应因客户所有权过滤而只能看到自己的订单、账单或服务。权限由服务端当前会话及用户角色决定，不由导航、请求参数或浏览器缓存决定。当前只有 `customer` / `admin` 两种角色，不额外制造一个缺少能力的“普通管理员”。

**全站权限不等于跳过业务一致性。** 管理员可以使用已实现的全站操作，但不能只改订单的 `status` 字段，让账单、收款记录、服务、历史快照和审计互相矛盾。本文件区分当前能力与缺口，不把需求清单当作已经实现。

## 当前能力

| 对象 | 管理员入口和能力 | 现有限制 |
| --- | --- | --- |
| 客户/角色 | `/admin/customer-accounts` 真实分页筛选、创建客户或管理员；按 ID 查看、修改名称/角色/启停、重置密码及撤会话 | 邮箱创建后不可改；仅 customer/admin 两种角色，无自定义权限矩阵；旧列表兼容保留 |
| 服务 | `/admin/services` 跨客户读取服务及准确的 `customer_id`；后台“服务管理”展示归属、规格、状态、到期与历史金额 | 只读；没有开通、暂停、重装、终止或控制器连接；不得做成可点击的假操作 |
| 订单 | 全站列表及 `/admin/orders/{id}` 直接详情，关联真实客户/账单、历史快照、脱敏支付尝试及审计；安全取消符合条件的未付订单 | 不提供任意状态编辑；没有精确关联的服务返回 null，不按名称猜 |
| 账单 | `/admin/invoices` 读取全站列表；`/admin/invoices/{id}` 直接读取指定账单；安全取消订单时联动作废账单 | 没有独立作废、人工收款、退款或贷项；管理员详情接口不提供代客户结账 |
| 审计 | 后台使用 `/admin/audit-events` 真游标分页及动作/操作者/UTC/所属账户筛选；客户 `/audit-events` 只读本人；旧 `/audit` 保持兼容 | 同库审计不是不可篡改日志；没有任意全文检索、导出或独立留存，也不向网页开放主机 journal |
| 商品与价格 | `/admin/catalog` 创建/编辑/复制、草稿/上下架与独立报价；原财务设置保留 | 不删除历史商品或增加资源开通；上架须至少一种启用币种有有效可用报价 |
| 运营设置 | 站点、财务币种、SMTP 设置、插件检查及版本检查/交接 | revision、CSRF、精度锁、秘密不回传等保护仍生效；网页不取得主机 root 执行权 |

商品分类支持类型、地区与节点的新增、改名、排序、启停及原因审计；节点仅作销售分类，没有线路或资源开通。引用、并发、迁移和历史保护见[商品分类](CATALOG_TAXONOMY.md)。

MySQL 旧客户列表、订单、账单、服务及旧 `/audit` 清单仍有最多 1000 条上限；新账户管理和审计独立分页，每页默认 50/最多 100。其他对象的全站读取**不表示已经实现完整分页、搜索或导出**。服务页显示当前载入范围，未载入的客户资料只能显示原始客户 ID，不能猜测归属。审计 `owner_id` 是事件所属账户而非操作者，见 [LOGGING.md](LOGGING.md)。

`GET /services` 等客户接口继续只读当前用户资源，管理员直接访问客户接口也不扩大其所有权；全站能力应走明确的管理员入口。客户接口不因后台需要而泄露其他人的 ID 或密码散列。浏览器同一用户 ID 的角色切换也必须清空管理员缓存并丢弃旧请求的迟到响应；这只是展示防护，不能代替服务端权限。

## 订单状态必须对应实际操作

| 操作 | 当前结果 | 必须保留的约束 |
| --- | --- | --- |
| 客户确认下单 | `pending_payment` 订单及 `unpaid` 账单 | 服务端价格/币种权威、报价检查、幂等键、不可变快照、原子提交 |
| 管理员取消未付款订单 | 同事务写入 `cancelled` 订单、`void` 配对账单、原因审计及取消事件 | 已付款、存在支付尝试、关联服务、配对或历史不安全时拒绝；管理员亦不能绕过 |
| 获准渠道的验签结算 | 同事务保存真实结算证据并使订单及账单 `paid` | 商户、金额、币种、精度、事件和渠道交易唯一性、持久幂等与审计 |

取消失败应明确说明状态冲突或尚不能安全取消。管理员看到的指引应是核对支付处理与记录，不是让管理员再“联系运营方”。请求或响应不确定时先复查，不能在网页上先画成成功。

人工线下收款、退款、冲正、续费和资源生命周期均未实现。后续如纳入范围，应分别设计有原因、权限确认、原交易关联、审计和幂等的业务操作，原子维护对应记录；**不能通过开放通用 `PATCH status` 或直接 SQL 改已付来替代**。已付历史不能靠改回未付来撤销，服务状态也不由订单下拉框冒充真实资源动作。

## 管理写入保护

账户写入要求原因及当前 revision（创建除外），事务内复核实际启用管理员。角色、启停、密码或会话撤销递增版本并撤销全部会话；仅改名称不强制退出。密码验证绑定所读账户版本，管理员操作不能被在途旧凭据登录绕过。禁止自降权/自停用，最后一个启用管理员受串行事务保护；允许自己重置密码或撤会话，成功后必须重新登录。密码不回传、不记日志或审计。

商品规格、可用状态与报价共用全局价格 revision，每次成功变更使旧确认报价失效；写入同时核对实际金额解析所用的 currency_revision，阻止未定价新币种的精度竞态，旧草稿不能自动借用新版号。复制生成新 ID 并强制草稿；草稿和下架商品不出现在公共目录。已上架但所选币种缺价的商品仍显示不可购买，不能用其他币种补价。上架须通过有效报价验证。不重写历史订单、账单、服务或套餐快照，不推导汇率。

## 仍未实现的范围

订单/账单/服务列表仍有既有 1000 条上限，未完成全库分页和检索；新账户分页不代表其他列表也已分页。真实资源生命周期、人工收款、退款、冲正及完整会计账本仍不在范围内。真实邮件/支付、公共 CA 续期与生产容量须分别验证。精确源码、实际测试、视觉截图与原生/发布门禁见 [VALIDATION.md](VALIDATION.md)，不能凭功能文档宣称全部验收。
