日期：2026-10-21（Asia/Shanghai）。本次仅交接本文与 `UI_API_REFERENCE.md` 两份文档，**不提供现有项目源码**。用户明确要求放弃现有 UI，由 Gemini 从零原创主导视觉、信息架构、交互与完整前端开发；不能沿用旧方案，也不是对现有布局局部修补。

## 1. 你负责什么

请为一个真实 IDC / 云服务计费系统，**独立设计并开发一套可运行的 Vue 3 + TypeScript 前端**，包含客户控制台与管理员控制台。我们负责后续隔离审查、接入现有 API、安全验证与回归；你负责视觉、信息架构、交互和完整前端实现。

- 不要求你读取本地源码或访问现有服务器，也不会提供 Git 仓库、密钥、账号或真实客户数据。
- 交付完整前端文件/可下载项目包与运行说明；不是只有建议、效果图、独立静态宣传页或一个无法接接口的 mock。
- 直接做设计开发，不再要求用户重复已经给出的审美和业务要求。
- 自主决定布局、组件、间距、颜色使用、圆角和动效，形成完整一致的原创设计；本任务没有需要继承的既有视觉结构。
- 语言是中文/English，默认中文；购买币种默认 CNY，支持 USD 及运营者配置的其他币种。
- 保持 Vue 3 + TypeScript，不切换 React/Next。不改动后端 Go + MySQL，不要求 Docker、新数据库、Redis 或真实资源开通。
- 产出应可构建为静态资源部署到原生 Linux/Nginx，兼顾 Ubuntu 22 等现有部署环境，不要求服务器运行新的 Node 服务。

## 2. 用户已经明确的审美方向

### Akile 内页与手机，不止首页

参考 <https://akile.ai/>。用户反复强调：**不能只看其首页，要看商品目录、选购流程、内页、手机排版、导航、抽屉和弹出框**。请实际查看你能访问的页面，说明具体观察与限制；看不到登录内页就明确说看不到，不能编造“已经学习”。不索要真实账号，不复制其品牌素材或客户数据。

### 苹果风，但不是视觉特效堆砌

用户想要苹果式的自然、清晰、克制与完成度：

- 信息层级明确、对齐准确、留白舒适、中文自然、字重和强调有节制。
- 有质感的表面、边界、微反馈和统一的组件语言，而不是浏览器默认表单随意拼接。
- 不要炫光、玻璃堆叠、泛滥渐变、巨型装饰标题、无意义统计卡、假图表或营销文案填空。
- 这是业务控制台，不是售卖概念的首页。页面首先帮助客户购买和查账、帮助管理员运营。
- 手机和桌面应像同一款认真设计的产品；自适应不是只做到“没有横向溢出”。
- 保留运营者可配置的站点名称、图标、公司信息和蓝/青/紫主题能力，但你可以自主设计其呈现方式。

### 让 Gemini 真正主导

请从真实业务任务出发，独立设计整个壳层、页面布局、购买路径、列表/卡片、抽屉和弹窗。视觉和信息架构由你主导，不预设圆角、边框、面包屑、侧栏宽度、页头高度或卡片结构。只遵守真实能力、API 约束、安全与可访问性，不把“技术上已通过测试”误当用户已认可审美。

## 3. 关键任务与交互要求

### 语言与币种偏好

自主设计清晰、自然、容易发现的偏好交互。当前语言/币种状态要可理解，在手机和桌面均不妨碍当前主任务；具体入口与呈现方式由你决定。

语言和币种是**独立设置**，中文可以配 USD，English 可以配 CNY。管理员的报表币种不得覆盖客户购买偏好；历史金额不能随当前选择改写。

### 抽屉和弹出框

用户特别重视抽屉与弹出框的完成度。请将它们作为完整设计对象：

- 抽屉要有合理分组、当前页、身份信息、层级和关闭方式；短屏不遮住底部入口。
- 弹框应有完整的标题、上下文、正文分组、校验/错误、确认与取消设计，不是一个白框塞表单。
- 手机短屏、横屏、键盘出现时，正文、安全说明、关闭和操作仍可到达。
- 键盘焦点明确，Tab/Shift+Tab不逃出模态，关闭回到合理入口；Escape、遮罩、关闭按钮、浏览器返回都符合当前任务约束。
- 写入正在进行或结果不确定时，不允许随便关闭后重复提交；由真实 API 状态决定反馈。

### 商品上架与购买必须方便

管理员需要真实商品管理：**新增、复制、编辑规格、独立定价、保存草稿、上下架**。这些能力已由 API 提供，前端应充分使用，而不是只改已有套餐价格。

客户应很容易：选择区域 → 比较配置和当币种价格 → 选择套餐 → 检查摘要 → 填服务器名称 → 创建待付款订单。你可以自主重组视觉和步骤，但不能省去金额确认或把下单描绘为已经付款/开通。

## 5. API 与业务硬约束

请以附件 **`UI_API_REFERENCE.md`** 为接口依据。不能虚构端点、字段、状态或成功响应；存在缺口时指出具体缺口，由我们处理，不要求修改后端来迁就视觉。

### 权限

- 当前仅 `customer` / `admin` 两种角色，不创造新的权限矩阵。
- 客户仅看本人，管理员应调用全站管理员接口；全权限不等于跳过业务规则。
- 服务端是授权权威，隐藏导航不等于安全控制。
- 退出、账户/角色变化时清除受限数据和任务状态，旧请求不能污染新身份。
- 保留自降权/自停用限制与最后一名启用管理员保护。

### 财务、购买与状态

- 金额、币种、价格、精度、报价版本及历史快照以API为准，不自动换汇，不浮点重算，不用当前商品/格式覆盖历史。
- 缺少所选币种报价的商品不可购买；不得借用其他币种价格。停用币种可按API用于历史/报表，不代表可供新购买。
- 商品复制创建新ID且为草稿；上架需有启用币种的有效可售报价。规格、报价等修改必须保留API的版本冲突机制。
- 下单需报价复核、幂等键及服务器名称校验；结果不确定应核对原订单，不自动新建或静默重试。
- 创建订单只创建待付款订单和账单，本身不扣款、不真实开通服务器。
- 取消仅限服务端允许的未付款订单，关联账单同时作废；不能取消已付款/支付处理中等不安全对象。
- 不能提供任意订单状态编辑、人工标已付、退款/冲正或真实资源开通；这些没有现成业务API。
- 付款返回页、渠道可用、请求已接受、实际入账是不同事实，不能提前显示成功。

### 日志、表单与错误

- 区分业务审计、HTTP请求诊断和主机日志；动作码不是HTTP状态，事件ID不是请求ID，所属账户不是操作者。
- 保留游标、筛选、列表上限和错误语义。部分旧清单有1000条上限，客户端筛选不能标成全库搜索；不能假装所有对象都已分页。
- 保留CSRF、会话、revision、currency_revision、幂等、字段校验和安全错误处理；不显示提供方响应/秘密。
- 首次读取失败不是空态；刷新失败保留可读缓存并说明可能过期；写入结果不明先核对，不自动重试。
- 商品/账户等危险操作提供原因、确认、处理状态及冲突反馈。不能删安全说明使页面更“干净”。

完成审计、服务、财务、站点/SMTP、扩展、更新、账户、登录与全状态一致性，检查中英文、主题和全设备。

2. 页面和组件的完整实现，不用省略号占位；不只交效果图、独立HTML或无法应用的建议。

5. 若你能实际运行，给真实运行截图与命令结果；不能运行就明确“待我们本地集成验证”，不能编造通过记录。
