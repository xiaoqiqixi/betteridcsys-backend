# 实施范围与版本边界

本页保留 Core 0.5.3 的历史范围，不是当前全部能力清单。当前操作从[首次使用](GETTING_STARTED.md)开始，版本变化见[变更记录](CHANGELOG.md)。历史调研与验收应结合对应提交及[验证记录](VALIDATION.md)阅读，不能互相替代。

## 客户与财务流程

客户按地区与独立币种价格选择套餐，核对规格和报价后创建待付款订单及账单。运营者维护品牌、币种、价格和启售状态；历史金额、币种及套餐快照保留。符合条件的未付取消原子作废配对账单并留下审计，不代替退款或资源撤销。

支付按[运行时插件合同](PAYMENT_PLUGINS.md)接入，使用独立 `aster.payment/1` 进程，无需与 Core 一同编译。已批准的验签程序负责渠道签名、商户和时间窗口验证；Core 已实现唯一支付尝试、权威订单和账单绑定、精确金额与币种校验，以及持久去重和原子结算。默认支付关闭，没有内置真实渠道；不能凭客户端跳转或未验签通知改变财务状态。渠道交易查询、撤销、退款、订阅、对账及特定渠道要求的回调应答尚未提供。

## 安装、升级与恢复

- [安装](INSTALL.md)先核对适用环境、同版本程序及资源，准备域名、TLS、数据库和私密输入，审查实际计划后明确执行。
- [升级](UPGRADE.md)区分当前与目标版本，先备份和隔离恢复，维护停写后检查兼容性、更新数据库并切换同版本前后端。中断从原检查点核实现场，不盲目重放。
- [恢复](BACKUP_RECOVERY.md)匹配版本、配置和秘密；摘要检查、程序回退与数据库恢复分别验证，不自动还原数据库。
- 后台只查询版本、形成审计交接和读取脱敏回执，主机管理权限保留在管理员明确运行的 CLI 中。

## 插件与后续开发

[SMTP](PLUGINS.md)与[支付](PAYMENT_PLUGINS.md)均为独立运行时插件，分别使用 `aster.smtp/1` 和 `aster.payment/1`，审批、进程身份、摘要及秘密边界分开管理。已批准的渠道验签实现仍须开发者审查和验收，Core 的业务校验与幂等结算不替代渠道签名验证。邮件或支付结果不明确时先核对，不自动重发。

后续改动围绕现有客户和管理流程的明确需要安排，先核对数据模型、权限、失败状态和验收范围。营销、代理、资源控制器或特定支付渠道不会随界面调整自动加入。实际源码、验证、正式发行和目标环境部署是分别记录的结果。
