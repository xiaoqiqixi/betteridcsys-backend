# 版本更新

[使用文档](../../docs/README.md) · [升级与回退](UPGRADE.md) · [备份恢复](BACKUP_RECOVERY.md)

## 更新前准备

- 使用有效的管理员账户登录后台；服务器操作由获准的主机管理员完成。
- 阅读目标版本的变更说明，确认当前版本、数据库和已启用插件满足兼容要求。
- 准备维护窗口、足够磁盘空间和完整备份；先完成隔离恢复演练。
- 使用所选正式发行版配套的工具和前端文件，不混用不同版本，也不从可变源码目录安装。

当前后台支持检查版本、生成升级交接和查看主机执行状态。**后台直接执行升级尚未提供**；交接完成不代表服务已升级。

## 检查版本

1. 进入管理员后台的版本更新页面，点击“检查官方更新”。
2. 核对当前版本、候选版本、发行说明和兼容提示。候选受固定官方来源约束，不能自行填写下载 URL。
3. 如果查询失败，检查服务器网络或只读访问授权，再重新检查。失败不代表已经是最新版本；过期的查询结果不能直接用于确认。

Core 与 SMTP 插件分别更新。更新系统不会自动新增支付渠道、启用资源插件或改变币种；历史订单与账单金额保持不变。

## 准备并执行升级

1. 在后台选择目标版本，确认生成升级交接。交接记录本次操作人、版本与来源，有效期30分钟。
2. 将交接通过安全途径交给主机管理员。它包含内部标识，不应作为公开附件，也不是授予任何人 root 执行权限的凭据。
3. 主机管理员按[升级手册](UPGRADE.md)核验发行文件、准备目标目录和计划，逐项审查实例、版本、备份、插件与 TLS，再确认精确计划摘要。
4. 执行器进入维护、完成备份、迁移数据库、切换程序并检查服务。准备文件、下载完成或返回交接回执均不算升级成功。
5. 站点恢复后，管理员重新登录，核对版本、商品、订单、账单、邮件和已启用插件。

详细主机命令、旧实例接纳与回退条件统一维护在[升级手册](UPGRADE.md)，不在本页另存一套命令。

## 查看进度

配置了主机状态导出后，版本页显示实际执行阶段。尚未配置、没有记录、记录读取失败和执行成功是不同状态，不能相互替代。

| 页面状态 | 含义与处理 |
| --- | --- |
| 等待主机管理员 | 后台已生成交接，尚未执行服务器升级 |
| 检查、备份、迁移或启动中 | 升级工具正在相应阶段，勿重复发起 |
| 升级完成 | 目标程序和 HTTPS 检查通过，继续完成业务核对 |
| 已恢复旧程序 | 已验证旧程序恢复，检查维护状态与原失败原因 |
| 需要人工恢复 | 保留原操作和现场，按升级手册排查，不删除记录后重试 |

网页关闭不会结束主机工具。网络断开或请求结果不明时，按原操作 ID 查看记录；不要再次生成一笔升级来猜测结果。

## 失败与回退

- 未切换前失败：保持当前程序，核对失败检查项；不能跳过来源、备份或兼容检查。
- 数据库已迁移：只在证明旧程序兼容当前 schema 时回退程序，不能直接替换旧二进制。
- 状态无法确认：保留维护状态、日志、备份和原操作 ID，由主机工具核对实际检查点。
- 数据库恢复：按[备份恢复手册](BACKUP_RECOVERY.md)执行明确的灾备操作，不自动覆盖现有数据。

不会自动回退操作系统、删除迁移记录、重算历史账单或重新提交支付。日志排查见[日志与审计](LOGGING.md)。
