# 安全边界与威胁模型

本文件适用于 Core 0.5.3；历史行为和验收范围以对应提交及[验证记录](VALIDATION.md)为准。

## 保护对象与信任边界

保护客户账号、会话、账单金额、订单所有权、数据库凭据、审计和未来开通事件。浏览器完全不可信，不能信任客户端提交的价格、客户 ID、角色或“支付成功”状态。当前目标为单机原生 Linux：systemd 管理 Go API、Nginx 提供 HTTPS 和静态网页、同机 MySQL 持久化。各服务使用独立身份；主机管理员仍具有高权限。多节点和高可用不在本次范围。

本版本不收集卡号，不存储银行卡或云平台密钥，不发送真实控制器动作。不要添加“后台手动改已支付”作为临时支付绕过。

## 攻击面与必须验收的控制

| 风险 | 设计控制 | 剩余风险 / 验证要求 |
|---|---|---|
| 跨租户读写 / IDOR | 服务端会话身份、资源所有权查询、管理员 RBAC | 必须用两个客户的真实 MySQL 数据验证每个资源与列表；隐藏按钮不算权限 |
| CSRF / 会话劫持 | HttpOnly cookie、生产 Secure、SameSite、变更请求 CSRF 与来源限制 | XSS 可绕过部分浏览器控制；检查注销、过期和错误来源 |
| XSS / 点击劫持 | Vue 转义、脚本 CSP self、禁止嵌入、禁止 MIME 嗅探 | 动态样式允许 inline；新增富文本、CDN 或支付 SDK 必须单独审计 |
| 重放 / 双击重复订单 | Idempotency-Key、数据库事务与唯一约束 | 并发与冲突载荷必须在真实 MySQL 上测试，不能只测内存 |
| 篡改金额 / 越权套餐 | 服务端登记币种及独立报价，0–6 位整数最小单位、精度锁和历史格式快照，币种纳入幂等请求 | 无自动汇率/换汇；税、折扣、退款和完整会计分录尚不支持 |
| 运营设置注入 / 越权覆盖 | 管理员 + CSRF + revision；设置/审计同事务；纯文本与 logo/theme 白名单 | 无 HTML/CSS/脚本或远程图片；支持链接仅展示不抓取，仍需运营方核对目标归属 |
| 历史身份 / 币种被改写 | 创建订单和账单时保存金额、币种与 issuer 快照 | 老数据缺快照时保持缺失；修改公司名不补写历史；账单不是税务发票 |
| 伪造付款与开通 | 默认关闭支付；独立批准的验签程序返回渠道证据，Core 重验已保存的账单绑定、精确金额/币种并持久去重、原子结算；outbox 不连接真实控制器 | 没有内置真实渠道；验签实现正确性、商户秘密及渠道实际验收由开发者负责，渠道查询/对账、退款和资源消费重试未提供 |
| SQL 注入 | 数据访问使用参数化查询；输入限制 | 后续动态排序/过滤字段必须白名单，审查错误响应是否泄露 SQL |
| 凭据泄露 | 随机秘密、受限配置文件、仓库忽略、非 root API、数据库不对外监听 | 文件不是 secret manager；主机备份、日志、发布归档仍需审查 |
| 暴力登录 / 滥用 | 服务端限速和请求大小限制应验证；边缘补充保护 | 内存限速不能实现多实例全局限速，也不是 DDoS 防护；已配置 nginx 单一 /32 可信来源和覆盖 X-Real-IP，真实 NAT/边缘信任链仍须测试 |
| 数据破坏 / 丢失 | MySQL 持久数据目录、事务、备份及隔离恢复流程 | 尚无自动异地备份、PITR、复制或高可用；本机数据目录不等于备份 |
| 内部误用 / 审计删除 | 审计事件与最小权限 | 同库审计不是不可篡改账本；需要独立日志保留和运维审计 |

这里列出的“设计控制”必须以代码和验收结果证实；没有测试证据的控制不能视为已获生产保证。

## 最小权限与部署加固

- API 使用无登录权限的 `aster` 身份，发布文件归管理员所有；systemd 模板限制写入、设备、内核接口和 capabilities。API 持久状态在 MySQL，无需可写发布目录。
- Nginx worker 和 MySQL 使用各自的系统身份；发行版 Nginx master 可能需要权限读取 TLS 密钥和绑定 443，不宣称全部原生服务以非 root 启动。按发行版服务模型验证实际权限。
- 数据库迁移身份仅用于本库 DDL，运行身份仅授予本库 SELECT/INSERT/UPDATE/DELETE；API 不可读取迁移、备份或 root 凭据。新安装由获准管理员确认执行器计划后创建专用账号和授权，已有实例核对并保留权限边界。
- 原生同机 Unix socket 使用显式 `MYSQL_ALLOW_INSECURE=true`，因为当前驱动配置要求 TLS 或这个例外。Core 0.5.1 将该例外限制为明确的 `unix(...)` 连接，TCP 使用此开关会被拒绝；仍须核对 socket 访问权限与账号绑定。跨主机扩展须重新审查 TLS 与信任边界。
- API 只监听回环；MySQL 不对外监听。禁止向 API 身份开放主机管理 socket、sudo 或服务管理权限。
- 生产 TLS、防火墙、SSH 权限、磁盘加密、日志保留、密钥轮换、依赖扫描与告警属于必须补齐的环境控制。
- 演示账号和内存模式不得出现在公开生产环境。不得通过设置 demo 来绕过生产配置错误。

云端 Ubuntu 24.04 已实际验证 systemd API、Nginx HTTPS、数据库与文件权限、API 重启、同二进制/schema 的发布目录切换及同实例新空库备份恢复，证据与源码对应关系见 [VALIDATION.md](VALIDATION.md)。该结果使用临时私有 CA 和合成数据，不涵盖实际域名、公共证书签发/续期、MySQL 进程或整机重启、跨版本迁移回退、独立实例/异地恢复及生产 RPO/RTO；宝塔适配亦未在实际面板主机验证。

## 账号生命周期缺口

没有邮件所有权验证、密码找回、MFA、自助改密、完整会话管理与账号封禁流程。在这些能力落实前，不适合公开自助商业注册。管理员必须使用独立强口令；通过 CLI 初始化不等于已完成安全的长期管理员管理流程。

## 官方 SMTP 的权限、审批与秘密

SMTP 默认关闭，只允许管理员通过会话、CSRF、来源和设置 revision 校验保存/主动测试。Core `0.5.0` 没有内置传输；独立 `email.smtp` 必须先经 root 安装、校验并明确批准。被动发现不执行文件或启动进程，网页不能上传/批准插件。

程序、manifest 与策略都由 root 管理、不可共享写入或使用链接。策略固定版本、manifest SHA-256、不同的非 root API/worker UID、socket 与最多八个精确 SMTP host/port。Core 每次调用验证文件/摘要与兼容区间，并在同一 Unix 连接上检查 peer UID/随机 nonce/版本/能力；握手失败不发送凭据，不重连转发原请求。宿主以验证过的文件描述符执行程序，清除继承环境/额外 FD、禁止新权限和 core dump，需要 Linux >=5.11；不支持时拒绝启动。

插件身份与摘要自报告防止误版本/意外替换，不是已被控制的 worker UID 的密码学证明。独立 systemd 身份、秘密不可达路径、只读文件系统、设备/内核/capabilities 及资源限制保护 Core 地址空间与秘密，**不是任意恶意代码沙箱**。已获发信能力的插件会接触本次 SMTP 凭据与内容并能访问网络；来源/代码审查和主机出口限制仍必要。

`/etc/aster` 为 root:root 0755，使插件能读取不含秘密的 `plugins.json`；`api.env` 为 root:aster 0640，`secrets/` 为 root:aster 0750。插件只能加入 `aster-plugins` socket 组，不能进入 `aster` 组或读取 DSN、会话秘密、迁移/备份秘密和 SMTP 加密密钥。Core 不持有 sudo 或服务控制权限；插件安装工具只校验/安装与批准，Core 主机执行器由获准管理员另行确认，才执行已核验 Core 的迁移/引导和既定服务动作。模板隐藏默认数据库路径；宝塔或自定义 socket/数据路径须补充实际不可达路径并在 service namespace 中验证，不能将默认路径规则视为所有数据库布局均已隔离。

用户名/密码只写，数据库仅保存 AES-256-GCM 密文；管理读取只给配置标志，公开设置不暴露 SMTP。主机加密密钥是受限的 32 字节原始文件，未设置不能启用/发送，无效文件拒绝 API 启动。插件只接收当前解密配置，不得到密钥。加密不能防御控制 Core 身份或 root 的攻击者；数据库和密钥分开备份，轮换不自动重加密，见 [备份恢复](BACKUP_RECOVERY.md#smtp-密钥备份恢复与轮换)。

目的地由后台配置与独立 root 策略同时限制，更换 host/port/TLS 模式必须替换完整凭据或同时清除并关闭。主机名/端口白名单是应用层检查，**不是出口防火墙或固定 IP 保证**；SMTP 可以指向明确获准的本机、私网或公共中继，DNS 与 OS 网络策略须独立审查。最低 TLS 1.2、验证证书链及 host 身份，认证不降级明文，不提供跳过验证。

测试限定单个收件人和固定内容，每个 Core 进程至少间隔 30 秒且仅一个在途请求。RPC 握手两秒、发送调用十二秒，较短 deadline 优先；该期限不包括本地文件读取/摘要，最终审计最多两秒。Core 不重试 RPC，SMTP 传输仅在 MAIL 前明确暂时失败时最多重连一次；开始 MAIL 后不重发。SMTP 接受不能回滚，panic/异常响应/发送后连接丢失都保守报告不确定。

插件 stdout/stderr 不写 journal，协议层丢弃原始 HTTP 错误输出；审计与接口只记录固定类别，不记录密码、用户名、密文、收件地址、正文、路径或服务商原始回复。故障排查记录 systemd 生命周期、策略 revision/版本/摘要，不打开请求内容日志。插件崩溃由有界 systemd 重启处理，Core 不自动回退或重发。

`EMAIL_PROVIDER=email.disabled` 不是 SMTP 总开关。正常停用先关闭 root 策略再停止 SMTP service，后台也可关闭设置；缺少加密密钥亦不可发送。已开始的请求可能使用旧审批/凭据，停用不能撤回接受，未知结果先核对记录，不能盲目重试。恢复/回退命令见 [PLUGINS.md](PLUGINS.md)。

真实服务商连通、SPF/DKIM/DMARC 与收件箱投递不由回环 TLS 测试证明。当前仅管理员测试，不能把插件可运行当作已有业务通知、邮箱验证或密码找回。

## 后台更新的独立信任边界

版本更新只查询固定官方仓库的正常 Release，管理员不能提交任意下载 URL、目标路径、shell 或 service 命令。更新说明是外部纯文本，不渲染 HTML/脚本；管理员入口受会话/RBAC保护，交接变更要求来源/Host、CSRF、严格请求及审计成功，客户端版本/摘要不能成为主机权限依据。

Web API 保持非特权且运行目录只读，不执行包内文件、改 unit/链接或连接主机管理 socket。主机 prepare/stage 工具独立核对固定官方 TLS/API 来源、版本/提交、资产与完整路径/类型/权限；交接不是主机执行授权。自 Core 0.5.2 引入的主机执行器由获准管理员另行启动，先读取 root 私密规格并生成计划，再以精确计划 SHA-256 确认。确认后才按既定动作创建身份/数据库/受限配置、迁移和引导、维护停写、验证备份、切版本及管理本站原生服务；不接受任意命令、URL或网页提供的主机路径。全新安装拒绝既有对象，升级核对真实版本/schema/插件/配置和恢复准备。文件 SHA/gzip/metadata 不证明隔离恢复，系统依赖、公共证书、无关服务和其他站点不由执行器接管。

SHA-256、GitHub asset摘要及未签名 PROVENANCE通过官方 TLS建立一致性和来源约束，**不是独立密码学签名**。官方仓库、账号、发行权限或渠道失陷仍可能提供自洽恶意资产；不宣称自动化防住恶意发行者。过期/冲突/不兼容或核验失败停止，不沿用缓存把未查询状态当最新安全版本。错误不包含 token、秘密、完整原始响应或环境变量。

执行器使用锁、持久计划和 journal 记录实际检查点；结果不确定时保留维护状态，resume 只核验原规格/摘要，不盲目重放。程序回退必须证明实际旧 schema 兼容并验证旧服务；不自动导入备份、删除数据库或执行向下迁移。实际验证范围以对应提交/run 为准，不能从设计宣称外部主机或生产恢复已验收。UI 请求、暂存、主机应用与业务验证分别记录，见 [UPDATES.md](UPDATES.md)。

网页只读单独脱敏回执：受控环境变量 `HOST_OPERATION_STATUS_FILE` 指向 root 管理、无链接且不可共享写入的普通文件，API 没有写权限，不读取私密 journal。管理员接口核对大小、所有者、权限、稳定读取和严格 schema，失败显示不可用；无回执或缓存不能证明安装成功。私密规格、计划、journal、凭据和备份保持 root 私密，不能为网页展示开放整个状态目录。

## 财务审计范围与未实现能力

Core 0.5.3 已实现支付运行时边界、账单权威校验和持久幂等结算，财务检查同时覆盖报价确认、金额精度、订单/账单状态、历史快照、权限与恢复一致性。没有内置真实支付渠道、主控/被控或资源开通，也没有完整会计分录、渠道查询/对账、撤销、退款/贷项、续费欠费、税费规则或特定渠道回调应答。待付款状态不能手工改为已付以绕过缺口，outbox 记录也不是开通授权。后续财务审计分阶段要求见 [FINANCIAL_MODEL.md](FINANCIAL_MODEL.md)。

## 修复与发布范围

维护版本修复强制 MySQL TLS 配置允许明文回退、IPv6 文本别名绕过进程限速、错误 JSON 媒体类型被接受、管理端账单详情所有权路径错误、迟到账单响应覆盖弹窗、同秒备份文件名覆盖等具体问题。新增设置输入/权限/并发审计、可配置独立报价、精度/停用约束和不可变历史的回归测试。测试通过只覆盖已执行路径，真实结果和剩余扫描/部署限制见 [VALIDATION.md](VALIDATION.md)。

公司名/地址/署名是纯文本；不接受尖括号、控制或格式字符。链接限制 HTTPS 公共形态 ASCII 域名，拒绝 IP、localhost、单标签、凭据、端口和片段；服务器不主动访问该地址。logo 和 theme 仅预设值，不提供通用上传/URL 代理。公开设置不会泄露邮件署名和账单地址；后端设置不是 DNS、TLS 或认证来源配置。

全新安装仅启用 CNY，升级保留旧 USD 历史。运营者登记三个大写字母代码、0–6 位精度及独立价格；使用后精度永久锁定，未完成付款或服务义务阻止停用，禁止删除代码或转换旧金额。数据库仅约束代码语法与整数上界，登记成员校验和业务义务由核心事务承担；直接 SQL 绕过仍可能破坏一致性。单币种聚合不混加，设置变更不能修改历史金额/格式/身份。支付插件返回的金额、币种和精度由核心与已保存的尝试及账单逐项比对；默认关闭的支付配置不会生成已付状态。语言切换不承担金融权威。

## 财务发布守卫

新客户端下单携带报价金额、精度和价格 revision，核心在事务锁内比较，变化时返回 `PRICE_CHANGED` 且不创建财务记录；已完成幂等重放返回原历史。为兼容旧客户端，quote 仍可省略，旧调用按执行时价格下单，不能宣称所有客户端都具备陈旧报价保护。后台价格修改影响套餐跨币种总开关，需审核实际影响范围。

迁移 007 与旧 USD/格式回填必须在停写窗口执行，先验证完整备份和隔离恢复。当前没有向下迁移、完整会计账本、续费/退款/核销或完整导出；不通过改 SQL 状态消除未完成义务。新分发原始程序与资源必须分别校验并按同一 Release 组装，暂存成功或 `compatibility_review_required` 都不表示可以自动应用。

Core 0.5.3 的支付数据库升级保留既有业务金额与历史快照；完成后，0.5.2 程序不能直接接回运行。程序回退与数据库恢复分别核验，不能通过删除支付记录或改迁移历史取得旧版兼容。

## 事故响应草案

发现越权/泄露时先阻止受影响入口和进一步写入，保留证据，不急于清空日志或删库。界定影响范围与起止时间、冻结相关会话、轮换泄露密钥、验证修复和恢复完整性。通知责任人与受影响方的流程、保留期限及适用要求需由实际运营方确定。不要把本说明当作法律或合规认证。

## 安装准备、预检与取消边界

Core 0.5.3 的 `core-manager.py` 仅由主机管理员明确调用。它独立核对固定官方仓库、标签、来源/构建及精确资产，受保护路径中持锁写入完整临时目录，再以不可覆盖方式原子发布。`manifests/PREPARED.json` 是本地收据，不能冒充官方 Release 清单或独立发行签名；`prepared` 不表示激活。发布后最终同步/日志失败会报告结果不确定并保留目录，不能盲目重试或删除现场。Web 没有相应 root 执行入口；prepare 不修改 `current`、服务、配置、秘密或数据库，后续实际动作由独立的确认式 `core-operation.py` 执行。

主机 `doctor` 只读文件和系统事实；API `-preflight` / `-schema-status` 只读配置和数据库元数据，不构造提供商、不发信、不迁移或建用户。检查前核对数据库账号的可见范围，迁移时保持停写；结果属于当时的检查，不证明所有权限、隐藏例程/事件、业务数据、备份内容或恢复可用。`BACKUP.json` 自动记录实际 schema 和已核验安装版本，不能替代隔离恢复。

未付取消在数据库事务中排除在途支付尝试；保留的旧编译期适配器兼容层仍会保守阻止取消，但不是当前渠道的接入方式。核心校验所有权、唯一配对账单、未付状态、不可变金额/快照及未处理创建历史；服务关联或处理结果不明时拒绝。订单取消、账单作废、审计和取消事件同事务提交；不得据此制造收款、退款、删除历史或执行资源操作。支付尝试一旦保存，停用插件或会话过期都不解除取消屏障，不能仅据 `unpaid` 字段判断没有在途交易。

## Core 0.5.3 支付插件

支付 worker 使用 `aster.payment/1`、独立审批身份和商户、固定程序及 manifest 哈希和专用非特权进程，无需与 Core 一同编译。已批准的验签程序（verifier）属于信任边界：开发者负责渠道原始通知的签名、商户和时间窗口验证；进程隔离不替任意第三方插件证明验签正确。插件没有数据库或 Store 接口，Core 从已保存的尝试取得独立预期，重新锁定并核对客户、订单、账单、金额、币种和精度。事件 ID 与渠道交易 ID 按 provider 分别唯一，结算记录、订单/账单已付状态、审计及 outbox 在同一持久事务内提交，合法重放不重复入账。

支付默认关闭，没有内置真实渠道。超时不自动重试或释放尝试；回调专用 CSRF 例外不影响其他业务接口，浏览器跳转或成功字段不能改账。当前没有渠道查询、撤销、退款、订阅、对账或特定渠道要求的回调应答（ACK），实际渠道、出口策略与秘密管理须单独审查，合同见[支付接入](PAYMENT_PLUGINS.md)。
