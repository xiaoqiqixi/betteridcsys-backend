# 验收范围与操作记录

本文件定义 Ubuntu 24.04 / amd64 单服务器原生方案的验证项目。真实执行结果见 [原生验证记录](VALIDATION.md)；下列复选框用于记录具体部署环境的验收。每次结论应附测试时间、提交/归档哈希、系统版本、环境和证据。历史候选、内存演示或离线预览不能替代本次真实数据库与服务验证。

原生自动化覆盖真实 systemd API、Nginx/私有测试 CA 的 HTTPS、最小运行权限、API 重启、相同 schema 的 A → B → A 链接切换及同一 MySQL 实例中新空库恢复。是否通过以对应 run 结果为准。它不重启数据库进程或整机，不访问真实业务域名，不申请公共 CA 证书，也不承担容量、异地灾备或真实服务商验收。

## 构建与环境

- [ ] 干净环境运行 Go 测试与 vet，前端 npm ci / typecheck / build 成功。
- [ ] 同提交原始 Linux amd64 程序及资源包分别双构建一致，资源无 ELF；Core 六资产/SMTP 五资产、来源和全部哈希匹配，无秘密、转储或缓存。
- [ ] 原生 MySQL 8.4 临时实例运行真实集成测试，不跳过；独立数据目录与 socket 在测试结束后受控清理。
- [ ] 发行版/版本、架构、资源及已有服务确认；systemd/Nginx 配置检查和真实启动完成。
- [ ] 目标主机开机恢复单独在维护窗口验证，记录 API/Nginx/MySQL 的启动顺序和恢复时间；不能由 API 重启结果代替。
- [ ] 迁移独立执行并先于 API 就绪，健康检查反映真实状态；MySQL socket 权限与狭义连接例外经过确认。
- [ ] MySQL 和 API `127.0.0.1:18080` 不对公网开放；站点只经 HTTPS 暴露。
- [ ] 前端生产构建在 CSP 下正常运行，SPA 深层链接刷新正常，无外部资源请求。
- [ ] API 以 `aster` 运行，Nginx worker 使用专用身份，应用/网页目录由 root 管理且不可被运行身份修改；数据库断开时 readyz 失败。

## 用户、会话和权限

- [ ] 匿名访问业务资源返回 401，错误不含数据库秘密。
- [ ] 错误密码、过期/伪造 cookie、注销后旧 cookie 均不可访问资源。
- [ ] 生产 cookie 具有 HttpOnly/Secure/SameSite；前端不把会话存 localStorage。
- [ ] 缺失/错误 CSRF、不匹配 Origin 的变更请求被拒绝；正确同源请求成功。
- [ ] 客户 A 不能读客户 B 的发票、订单、服务或审计，列表也不泄露。
- [ ] 客户不能访问全部管理接口，不能通过提交 role 或 owner 字段提升权限。
- [ ] 登录失败限速、密码规则、请求体上限和异常 JSON 均经过负向测试。
- [ ] 两个真实来源经同机 TLS Nginx→API 的限速独立；伪造 X-Real-IP/X-Forwarded-For 无效，API 的精确回环代理信任与真实连接匹配。

## 订单、金额和持久化

- [ ] 请求里的伪造金额被忽略/拒绝，价格与币种只由服务端决定。
- [ ] 同一个幂等键与相同请求重试返回同一订单；冲突请求被拒绝。
- [ ] 真实 MySQL 并发请求不重复生成订单/账单/审计；事务中断不产生半完成状态。
- [ ] 重启 API 后用户、订单、账单、幂等数据和 outbox 保留。
- [ ] 数据库进程重启后的持久性单独验证；记录实际实例和重启结果。
- [ ] 从真实已发布 Core 0.5.1 安装实例升级到明确新源码候选；核对原/新运行程序 SHA、UID、静态资源、登录和业务数据，不把同一程序的 A/B 目录切换当作跨版本升级。
- [ ] 金额使用整数最小货币单位，UI 格式化不改变服务端金额。
- [ ] 登记币种独立报价；缺价/禁用币种不能下单；查询统计不混加币种，待付总额不受 1,000 条列表截断影响。
- [ ] 同键改币种冲突；订单/账单金额、币种和 issuer 快照在价格/设置变更后保持不变；旧缺失快照不补写。
- [ ] 全新安装仅 CNY；旧 USD 价格/历史/默认项升级保留；公开停用元数据不进入新订单选择器。
- [ ] 0–6 位独立十进制报价无浮点舍入；正数上界、零价/负数/前导零/指数/超精度及未知或非法代码拒绝。
- [ ] 已使用精度永久锁定、代码不可删除；未付款订单/未付账单/非 terminated 服务阻止停用，审计与配置同事务回滚。
- [ ] 新订单报价条件变化返回 PRICE_CHANGED 且不创建记录；完成幂等重放返旧快照；无 quote 的兼容客户端仍按执行时价格，限制明确。
- [ ] 新订单套餐快照和订单/账单/服务币种格式持久不变；旧缺失规格不从当前套餐补造。
- [ ] 迁移 1–7 checksum、升级/重复执行和已知中断恢复通过；未知版本及篡改 checksum 拒绝。
- [ ] 未接入支付时 checkout 返回 PAYMENT_NOT_CONFIGURED，没有付款成功假象。
- [ ] 不产生真实 VPS、虚构 IP 或“已开通”确认；outbox 仅保存待集成事件。

## 操作体验

- [ ] 桌面/窄屏布局、键盘、焦点、表单标签、错误提示可用。
- [ ] 加载中/空数据/网络断开/401/403/503 均有清楚状态，不静默假成功。
- [ ] 重复点击订单提交不会重复下单；退出后敏感视图清除。
- [ ] 演示与离线预览标识明显，生产不显示已知演示凭据。
- [ ] 简体中文/English 与登记币种独立选择；全新默认中文/CNY，升级保留旧默认项，刷新后偏好正常；未知文案安全回退。
- [ ] 管理员站点设置常用/高级分组、预览、保存和并发冲突可用；客户不能读取私有字段或写入。
- [ ] 危险链接/HTML/脚本/控制字符拒绝；展示地址不会改变 DNS、TLS 或认证来源；历史抬头不跟随当前设置变化。
- [ ] 账单关闭后迟到响应不覆盖新弹窗；不确定订单重试保留原键/请求，不能静默生成新订单。

## 更新与恢复守卫

- [ ] 主机管理员先审查受保护规格与只读计划，再明确确认 SHA-256；网页、交接、下载和目录准备不能授予执行权。
- [ ] 全新安装实际创建专用身份、秘密、数据库/schema、首位管理员、配置和服务；拒绝已有实例/账号/数据库/unit，不覆盖旧数据。
- [ ] 原生安装的开机启动选择明确；实际 enable/is-enabled 与服务启动分别记录，整机重启另行验证。
- [ ] 升级使用同一实例锁、有效 journal、维护停写、已验证实际备份、版本/插件/schema 检查；迁移和 API 运行身份分开。
- [ ] 实际中断后用原操作和摘要恢复；重复成功操作不重启服务、不重复管理员或数据库变更；不确定 DDL 不盲目重放。
- [ ] 新程序无法启动时，仅在旧程序完整 schema 校验通过后恢复旧程序；不兼容/未知结果保持维护，不自动导入或降级数据库。
- [ ] 受保护回执由实际非 root API 读取，管理员 GET 与客户拒绝均验证；网页显示实际执行结果、不可用和业务复核要求。
- [ ] 007 在停写及已验证恢复副本上执行；14 表数据/格式完整，未知版本和冲突结构拒绝，旧 schema 恢复不靠删除字段降级。
- [ ] 新 schema 2 交接与 BUILD 3 精确绑定分发；旧四资产仍可只读核验，旧已发布字节不改变。
- [ ] 缺备份为 backup_required；已选插件兼容区间未经独立核实时为 compatibility_review_required，不显示 applied 或更新完成。
- [ ] SMTP 1.0.0 在 Core 0.5.0 被拒绝；1.1.0 声明区间与真实 root 策略/程序/UID/socket 核对后才可启用。

## SMTP 专项

- [ ] 未安装/未批准/不兼容插件不能发送；被动发现 trap/未知程序不执行，核心仍启动并服务业务。
- [ ] 包外/包内 SHA、精确文件集合、ELF/版本/兼容区间、root 属主与所有祖先、软/硬链接、共享写入、未知/重复/超限 JSON 均有负向检查。
- [ ] 独立 API/worker UID、peer credentials、socket 权限与同连接握手验证；错误版本/断线/非法响应不接收凭据，不在另一个连接重放发送。
- [ ] 真实 Linux 程序安装、独立补丁版本替换、旧版回退和插件崩溃/有界重启期间，Core 二进制 SHA/PID不变且健康、订单/账单业务继续响应；每一步留存证据。
- [ ] 插件不能读取 API 环境、DSN、会话/SMTP 加密密钥或本机数据库 socket；无 sudo/服务管理能力，继承环境/额外描述符不传入。
- [ ] 主机 root 策略 revision 与后台设置 revision 分开校验；精确 host/port 必须批准，关闭/坏策略/错误摘要不会发信。
- [ ] 默认关闭；缺少密钥不能发送，无效密钥文件拒绝启动；未知/重复/null 字段及不匹配 revision 被拒绝。
- [ ] 匿名、客户、缺失 CSRF 或错误来源不能保存/测试；读取不泄露用户名、密码或密文，保存配置与审计同事务。
- [ ] 同时更换服务器与完整凭据；清除两项需关闭。错误密钥恢复需要完整替换，不能静默丢失旧密文。
- [ ] STARTTLS/隐式 TLS、证书/主机名拒绝、认证、时限、取消及限速在本地 TLS 夹具验证；固定测试内容且仅一个收件人。
- [ ] SMTP 接受与收件箱投递分别记录；MAIL 后不自动重发，DATA 结果不确定时不盲目重试。
- [ ] 数据库与密钥分开备份；隔离恢复先不加载密钥，解密验证保持关闭，单独核对真实服务商授权与投递范围。
- [ ] 插件 stdout/stderr 不进入 journal；接口/审计没有秘密、正文、收件人或原始上游回复，发送后不确定结果不能被标成可安全重试。

## 后台更新专项

- [ ] 匿名/客户不能访问更新管理，检查/交接变更需要正确CSRF/Origin/Host；不接受任意仓库URL、安装路径、命令或凭据值。
- [ ] 正常Core/SMTP标签、官方身份、成功构建来源、按分发类型的精确资产/摘要/兼容和纯文本说明严格验证；草稿/预发布/不兼容/不完整资料不得交接。
- [ ] 交接前重查候选与当前状态，审计失败/过期/冲突/网络不确定不显示安装成功；状态为待运维处理。
- [ ] Web非特权且不执行、安装、迁移、切换或控制service；主机工具独立重新核对官方来源，锁/journal/不可覆盖暂存与失败状态通过负向检查。
- [ ] Core缺备份保留backup_required，文件SHA/gzip检查不代替恢复演练；stage只暂存，真实应用、schema迁移/回退和业务验证另行记录。
- [ ] GitHubTLS/摘要/未签名PROVENANCE不被描述为独立发行签名；日志/网页/归档不泄露token或完整环境。
