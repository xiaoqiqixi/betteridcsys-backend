## 版本和范围

- Core API / plugin-host、前端 package / lock、插件管理器默认 Core：`0.5.10`。
- 独立 SMTP：**1.1.0**，`aster.smtp/1`，兼容 `>=0.4.0,<0.6.0`，不重新发布；默认关闭，仅支持管理员固定测试邮件。
- 独立资源插件候选 **0.1.1**（旧本地 0.1.0 目录不覆盖）；协议 `aster.resource/1`：最低 Core **0.5.10**、上界 `<0.6.0`。旧正式 0.5.9 没有此协议，不能用其版本号声明支持。资源插件另行构建、核验、安装和批准，不放入 Core 六资产。
- 支付仍为 `aster.payment/1`，最低 Core 0.5.3；不增加真实渠道，不动金额、支付幂等、币种精度和历史快照。
- 数据库继续 **schema 13 / 23 表**；没有新增 SQL，001–013 内容和校验和不变。
- 保留当前主线的客户/管理员界面、目录/商品配置和显式资源任务对接；不增加自动开通 worker、异步服务回填或支付能力。主控 `accepted` 不是 VM 运行证明。

## 为什么必须新发行

旧 v0.5.6–v0.5.9 的源提交已不在重写后的 main 祖先链。旧资产保持原样且不放宽校验时，重新 prepare/stage 仍会拒绝；新主线的版本号和新正式发行才能重新建立来源连续性。旧新 SHA 映射只用于追溯，不是白名单。

新 `prepare` / `stage` 继续校验选定源码、当前 main 祖先、构建策略树、成功 run/attempt、精确六资产和源码副本，**生产 ancestry 条件不变**。已存在旧目录按真实 PREPARED 收据、文件、BUILD、路径和迁移前缀独立核验；缺收据不得伪造，修改过的目录不能假称正式准备。详细前提及停写/备份/恢复步骤见 [UPGRADE.md](UPGRADE.md)。

新增离线回归覆盖：

1. 0.5.10 当前 main 祖先来源通过实际 prepare/stage；分叉 source、错误 merge-base、分叉 policy 继续拒绝，失败不发布目录、不切活动链接。
2. 通过实际 prepare 函数生成的 0.5.9 与 0.5.10 目录，保持 13 份相同迁移；升级在无网络回取旧来源的条件下使用真实本地收据，保留旧目录/备份并切换目标。
3. 删除旧 PREPARED 收据后，计划被拒绝，没有服务/数据库副作用，不自动重建收据。
4. 版本、SMTP 兼容、资源最低 Core 与六资产发布正文一致；0.5.9 资源兼容声明被拒绝。

这些是合成 GitHub/ELF/数据库/服务夹具，不是公开资产或真实主机升级验收。Linux 原子重命名及系统接口不应为适配 Mac 测试而放松。当前实跑与未跑明细见 [VALIDATION.md](VALIDATION.md)。
