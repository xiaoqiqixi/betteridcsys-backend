# W07-B1：排队中的身份写入与会话撤销

2026-10-26。此切片先实现 W07-B 的会话事务边界，不把它当作 revision、显式全设备撤销、MFA 或整套权限功能完成。

## 已确认的现状

`Require` 在进入处理器前检查当前会话、权限和 CSRF；创建/修改账户在 `identity_lock` 内再次读取当前操作者权限，但没有再次确认该物理登录会话仍存在。请求如果已通过认证、随后在读取请求体或等待事务锁时停留，期间退出登录或重置密码，原请求仍可能继续写入。

## 本包合同

1. 保留现有 HTTPS、Origin、Secure Cookie、CSRF、当前授权、有界委派、自降权禁止及最后管理员保护。
2. 仅在请求内携带已认证会话的 hash 与用户 ID，不持久化/记录原 Cookie，不扩展公开 User DTO。
3. 身份写事务顺序：`identity_lock → 锁定当前会话并确认 owner/有效期 → 当前管理员及目标授权 → 原账户更新/审计 → commit`。
4. 会话不存在、已到期、owner 不符或缺少内部认证证明：401；数据库错误不是认证成功，也不伪装成用户拒绝。
5. 会话锁定读取使用 InnoDB 当前读；等待结束后再判断有效期，不能沿用请求入口的旧时间。注销也按相同 identity→session 锁顺序串行化。
6. 已提交的资源任务不因退出登录被回滚；本包只封闭账号创建/修改，不声称所有资源写事务已具备同样 fence。
7. 无新增 SQL、发行版本或 UI 入口。财务金额、支付、币种及历史快照不变。

## 先验收的公开边界

沿用生产身份 HTTP Handler + 隔离真实 MySQL：登录获取真实 Cookie/CSRF，在 POST/PATCH 的请求体首次读取处阻塞（已经通过入口认证），完成注销/改密/时钟推进后再释放。断言收到完整 401，账户与身份变更审计没有产生副作用；不把网络错误当拒绝。

- POST 新增成员：排队期间注销，不能创建账户。
- PATCH 修改成员：排队期间注销，不能更新目标。
- PATCH 修改成员：其他管理员重置操作者密码后，旧请求不能继续。
- POST/PATCH：入口通过但会话随后到期，不能继续。
- 同一用户另一条仍有效会话、重新登录后的新会话仍可正常管理；不扩大注销范围。
- 保留所有原权限、最后管理员并发保护、审计失败回滚及真实浏览器回归。

现有包内 Store 测试改用真实持久会话构造内部证明并在每次调用后清理，不能为测试添加生产 bypass。新增竞态用例必须先在旧实现上真实 RED，再修复并完整回归。

## 后续仍属 W07-B

用户 revision/旧表单冲突；显式全设备撤销；撤销前在途登录的代次检查；独立身份操作不可变回执与 actor+target 未知结果锁；专用 UI 核对与有限写入浏览器验收。当前字段相符不是原操作成功证明，通用 VM 操作回读也不能解锁身份写入。
