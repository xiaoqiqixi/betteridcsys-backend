# 内置升级：财务整站、云主控与计算节点

## 目标与范围

管理员在后台完成“检查版本 → 查看变更 → 预检查 → 确认升级 → 查看结果”，不必每次登录服务器拼命令。财务前后端按验证过的组合升级；云主控与被控按兼容矩阵独立升级。关闭页面或网络中断不取消已受理操作，也不重新发起同一升级。

本文是实施合同，不是已发布功能说明。现有财务后台只有版本查询、手工主机交接和只读回执；现有云安装器只支持安装/恢复同一次安装，不能据此宣称支持运行中升级。

保持 Go + Vue/TypeScript + MySQL，Ubuntu22.04/24.04 amd64 原生服务。只升级应用，不做操作系统发行版升级、自动重启宿主机、接管其他服务或改变网络。金额算法、支付幂等、币种、历史商品/订单/账单快照及支付插件配置不在此次变更范围内。

## 使用流程

### 财务整站

1. 管理员进入“系统更新”，查看真实当前版本、上次检查时间、稳定版变更和兼容情况。无网络时显示未能检查，不写“已是最新”。
2. 选择一个明确版本进行预检查。检查来源、前后端配对、现有安装收据、磁盘、数据库、插件、备份配置、TLS 与维护能力。预检查不迁移、不切换、不停服务。
3. 页面列出目标/当前版本、短暂停机影响、备份位置的安全名称、插件阻碍、是否支持程序回退；重新认证后明确确认该计划摘要。
4. 服务端持久化原操作 ID、计划摘要、操作者和审计，再交给本机升级服务。财务写入进入维护窗口，停 API，实际生成并核验备份，再迁移、切换整站版本、启动服务、检查 HTTPS 和数据库。
5. 页面以真实阶段显示进度。API 短暂重启时提示“正在重新连接”，不伪造百分比、不关闭失败详情；恢复后读取原操作。会话过期必须重新登录。
6. 只有检查确认目标版本实际运行才显示“升级完成”；保留业务检查提示。失败明确区分未改变系统、已恢复旧程序、需人工恢复。

### 云主控

使用相同流程，但备份包含主控库、配置/证书引用与控制任务状态。先阻止新资源写任务，等待运行中任务进入协议允许的稳定状态；不能直接杀掉或重发未知任务。兼容预检查覆盖所有已准入节点版本、节点协议与 journal 版本。

主控升级不修改财务库，不以财务付款状态判定资源任务成功。现有主控仍使用受限 root UID；不能称为已完成非特权拆分。增加网页执行入口前，必须将管理 API 与特权安装执行器分离，实测新运行 UID 的数据库/TLS/静态文件/日志权限。

### KVM 被控

主控支持选择节点并生成滚动计划，默认 `max_unavailable=1`。节点进入维护后拒绝新资源任务，等待正在执行的任务稳定，再交给节点本机独立升级服务。该服务不能随被控进程重启一起消失。

升级被控程序不停止客户虚拟机、不重启 libvirt、不重装 QEMU、不重写桥或 netplan。核验新被控进程、mTLS 身份、协议版本、心跳和 journal 后，按原维护状态恢复准入。任一节点失败或结果不明即停止后续批次；不盲目升级其余节点。

兼容矩阵决定主控/节点先后顺序，不假定永远主控先升级。当前没有真 KVM 宿主，因此进程重启与 VM 连续性只可先做隔离执行器测试，真实 VM 连续运行、迁移/网络兼容仍明确待验。

## 组件与信任边界

| 组件 | 可以做 | 不可以做 |
| --- | --- | --- |
| 浏览器 | 查看固定来源的候选、提交版本与计划确认、读取操作状态 | 指定 URL、shell、路径、unit、DSN；上传 root 凭据；解释 Release 文本为指令 |
| 财务/主控 API | 当前会话授权、持久化意图和审计、访问受限本地协议、返回脱敏状态 | 调用 sudo、执行安装脚本、写程序目录、读取升级私密 journal |
| 本机升级服务 | 在 root 固定策略允许的实例上核验官方制品、执行明确版本的升级动作、导出状态 | 接收任意命令/路径/仓库参数、关闭来源校验、接管其他实例或执行系统升级 |
| 节点升级服务 | 核验节点维护许可与版本，保存/恢复被控进程状态 | 停客户 VM、清空任务历史、在升级时擅自操作宿主网络 |

安装器经主机管理员确认后安装本机服务与 root 所有策略。现有实例没有该服务时，后台说明需要一次受控安装，不能假装已可升级。默认只接受稳定版；Cloud RC 必须由主机策略与管理员共同明确选择预发布，不自动把 RC 当稳定版。

本地协议使用固定 Unix socket、内核 peer credentials 和精确 UID。路径及所有祖先必须受保护；请求大小、有界读取时间、未知/重复字段、版本和动作白名单均严格检查。服务不继承 Web 环境变量、工作目录或 PATH。root 私密文件不得放在 Web 可写目录。

即使只允许官方版本，受侵入的 API 仍可能造成可用性影响；本机策略、冷却时间、单操作互斥、受支持版本范围和独立审计是限制，不是“无特权风险”的保证。

- 前端发布静态文件包、内容清单和构建来源；包内 manifest 不是签名。独立验证器必须核验固定 GitHub 仓库 ID、工作流身份、提交、成功检查和发行资产；不能只检查自带 SHA256。
- 旧单仓库 raw 分发格式与新组合格式分别解析；不把多来源伪装为同一 source SHA，不放宽原格式字段。

- 旧实例迁移需要可核验的原安装收据与匹配备份。不伪造旧收据、增加旧/新 SHA 绕过名单或修改旧发行附件。
- 失败的下载/校验保留错误，不回退 demo、本地包或未验证镜像；依赖安全扫描是发行阻断项。

## 授权、持久性与并发

采用现有管理员身份边界。新权限只授予明确系统升级能力；客户、普通操作员/只读用户、资源插件均不可执行。管理员仍不得跳过来源、备份、状态机与兼容检查。

1. 创建计划、确认执行、恢复和程序回退均要求当前有效管理员、严格 Origin/CSRF、速率限制及短时重新认证。重新认证凭据只在 API 验证，不能传给升级服务或写日志。
2. 计划绑定组件、实例、当前/目标版本、安装来源、配置版本、插件策略和兼容快照。确认时重新检查；任一变化返回冲突，不能换成新计划自动继续。
3. 事务内对原会话、当前角色与修订进行授权，写不可变意图和审计。持久化后才返回已受理。数据库提交结果不明时只查询原 ID，不另造请求。
4. 本机升级服务在第一个变更动作前，独立核对原会话/授权记录仍有效。其数据库身份仅能读取必要授权记录，不授予账务写权限。校验/领取使用短事务，不能持有数据库锁运行下载或升级。
5. 授权被领取并进入执行后，登出不强行中断半次迁移；后续按原确认计划安全完成或恢复。领取前的撤权、注销或过期必须拒绝。
6. 相同请求 ID + 相同意图只返回原操作；不同意图复用 ID 返回冲突。主机每实例一个升级锁；云批次还有节点独占锁，不能仅靠前端禁用按钮。
7. root journal 先原子写入并同步检查点再做对应副作用。进程崩溃后根据原 ID/实际状态核对，不能凭计时重试未知迁移、切换或节点操作。

## API 与状态合同

新协议为单独的 `aster.upgrade/1`，不改变现有手工交接的授权含义。以下为拟新增端点，实施时分别适配现有财务与云 API 前缀/错误封装；上线前补入各 API 文档。

| 方法/相对路径 | 输入与输出 | 副作用 |
| --- | --- | --- |
| `GET /upgrades` | 当前版本、服务可用状态、候选及最后检查时间 | 无 |
| `POST /upgrades/check` | 空对象；受限官方查询 | 查询并保存检查结果，不执行程序 |
| `POST /upgrades/plans` | 稳定 request ID、精确 candidate ID、目标组件/节点 ID | 持久化预检查计划，不改运行服务 |
| `GET /upgrades/plans/:id` | 计划摘要、检查项、影响与过期时间 | 无 |
| `POST /upgrades/operations` | request ID、plan ID、精确 plan SHA256、重新认证结果和确认 | 原子受理，返回原 operation ID / 查询地址 |
| `GET /upgrades/operations/:id` | 当前真实阶段、失败码、版本与可用恢复动作 | 无 |
| `POST /upgrades/operations/:id/recovery` | 独立 request ID、原 plan SHA256、明确恢复动作 | 受控恢复，不直接导入数据库 |

严格限制 JSON、ID 格式与字段；禁止重复/未知字段、URL 或路径输入。错误区分 400 格式、401 会话、403 权限、404 未知对象、409 计划/锁/幂等冲突、503 升级服务或来源不可用。网络错误不得计为业务拒绝成功。

状态：`planned → queued → verifying → maintaining → backing_up → migrating → activating → checking → succeeded`；任一阶段失败只能进入有证据的 `failed`、`rolled_back` 或 `needs_recovery`。下载有可信长度时可显示字节进度；迁移与重启不显示编造的百分比。过期计划只标 `expired`，从未开始不能标“已取消升级成功”。

状态响应带 schema、operation ID、revision、观察时间、当前/目标版本、阶段、稳定错误码、维护/备份/迁移/程序切换/服务健康事实。秘密、文件路径、原始 stderr、SQL 和令牌不进入公开状态。旧 finance 回执仍严格解析，新增协议不将旧字段零值当证据。

### API 重启期间

使用既有同源认证端点，不新增匿名进度服务器，不向 URL/localStorage 放长期状态令牌。浏览器保留原 operation ID，重连后先恢复会话再查询；暂时不可访问只说明连接中断。执行器与 journal 独立于 Web 进程存活，主机工具可按原 ID 查私密恢复记录。

## 备份与回退

备份须实际完成并验证摘要、版本、schema、配置/密钥引用与恢复元数据，才允许迁移。备份失败不得继续。没有做过恢复演练必须提示风险，不能把“文件存在”说成“可恢复”。

迁移只追加新 migration，不修改历史 SQL。财务员工权限的在途 014 保留，不抢占编号；升级表号在合入完整 schema14 后分配。云当前 schema12，新升级表须独立追加并覆盖断点和结构漂移。

程序回退仅在旧程序可读现有 schema/journal 且原配置/程序均可验证时允许。数据库恢复是明确的灾备操作，不自动覆盖现库，也不以回滚按钮自动删除新数据。缺少兼容证据进入 `needs_recovery` 并保留维护状态。

## 页面细节

- “系统更新”只展示操作所需信息；常规视图不显示“真实 API/同源会话/数据来源”等开发提示。
- 当前与目标版本、发行日期、变更、检查结果、影响、备份要求分层展示。Release 文本转义显示，不渲染任意 HTML。
- 确认弹层有明确组件/节点数量，默认焦点不落在危险按钮；Esc、焦点返回、键盘、窄屏滚动和长版本号均验收。
- 执行中按钮防重复，离开页面不会取消主机任务；返回页面恢复原进度。失败后保留原 ID 和可解释的下一步，不给笼统“重试”按钮。
- 中英文、浅/深色、loading/empty/error、减少动态效果均遵守现有设计。视觉设计交给 Gemini；只传需求和接口，不传源码、旧图或凭据。
